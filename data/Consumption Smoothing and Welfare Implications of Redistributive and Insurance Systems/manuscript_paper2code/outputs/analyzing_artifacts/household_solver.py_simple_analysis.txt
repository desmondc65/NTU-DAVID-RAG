The `household_solver.py` module is the computational core of the model. It solves the life-cycle optimization problem for three types of agents: Single Males, Single Females, and Married Couples. Because the state space for married couples is high-dimensional, the implementation must rely on **Numba-accelerated** functions to ensure the General Equilibrium loop converges in a reasonable timeframe.

### 1. Utility Function Logic (`utility_function`)
The utility function must handle both single and married contexts, incorporating the equivalence scale $\eta$ for joint consumption.

*   **Functional Form:** $u(c, n, g) = \log(c) - \theta_g \frac{n^{1+\sigma}}{1+\sigma} + v_g$.
*   **Parameters:**
    *   `sigma`: Inverse Frisch elasticity (from `preferences.sigma` in `config.yaml`).
    *   `vg`: Gender-specific constant to ensure utility is strictly positive (required for endogenous survival logic).
    *   `theta_g`: Disutility of work, calibrated to match gender-specific work hours.
*   **Married Couples:** The collective utility is $U(c, n_m, n_f) = u(c/\eta, n_m) + u(c/\eta, n_f)$.
    *   `eta` (1.7) accounts for economies of scale in consumption.
    *   Weighting: Equal weight (0.5) is placed on each spouse's utility.

### 2. Retirement Phase Solver (`solve_retirement_phase`)
Ages $j \in [9, 15]$ (65 to 99). Households do not work ($n=0$) and receive pensions.

*   **State Variables:** Assets ($k$), Average career earnings ($\tilde{e}$), Health status ($h$).
*   **Decision Variables:** Consumption ($c$), Next-period assets ($k'$), Medical expenditure ($m$).
*   **Budget Constraint (Single):**
    $(1 + \tau_c)c + \phi m + k' = k + y^d_S(SS(\tilde{e}) + rk)$
    *   $\phi$: Copayment rate (20%).
    *   $y^d_S$: Disposable income via the Benabou-Heathcote tax function: $\lambda_S y^{1-\tau_S}$.
*   **Health and Survival:**
    *   Survival $s_{j,g,h}$ is determined by current health $h$ using the logistic function (Section 4.2).
    *   Medical spending $m$ produces new health capital: $I(m) = H m^\gamma$.
    *   Next-period health $h'$ evolves: $h' = I(m) + (1-\delta_{h,j})h$.
*   **Married Logic (Transition to Single):**
    The value function for a couple must account for three survival outcomes at $j+1$:
    1.  **Both survive:** $\beta s_{j,m,h} s_{j,f,h} V^M(j+1, k', h', \tilde{e}')$.
    2.  **Husband survives, wife dies:** $\beta s_{j,m,h} (1-s_{j,f,h}) V^S(j+1, k', h', \tilde{e}', \text{male})$.
    3.  **Wife survives, husband dies:** $\beta s_{j,f,h} (1-s_{j,m,h}) V^S(j+1, k', h', \tilde{e}', \text{female})$.
    *   *Note:* The survivor inherits the pooled assets $k'$ and health status $h'$.

### 3. Working-Age Solver (`solve_working_phase`)
Ages $j \in [1, 8]$ (25 to 64). Households choose labor supply and accumulate pension rights.

*   **State Variables:** Assets ($k$), Productivity shocks ($z$), Average career earnings ($\tilde{e}$).
*   **Decision Variables:** Consumption ($c$), Next-period assets ($k'$), Labor supply ($n \in [0, 1]$).
*   **Budget Constraint (Single):**
    $(1 + \tau_c)c + \pi + k' = k + y^d_S(w z \epsilon_{g,j} n + rk)$
    *   $\pi$: Insurance premium (fixed rate $t \times \text{earnings}$).
    *   $\epsilon_{g,j}$: Deterministic age-gender wage profile.
*   **Budget Constraint (Married):**
    The paper assumes separate taxation for married individuals.
    $(1 + \tau_c)c + \pi + k' = k + y^d_M(w z_m \epsilon_{m,j} n_m + rk/2) + y^d_M(w z_f \epsilon_{f,j} n_f + rk/2)$.
*   **Earnings History:** $\tilde{e}$ updates via $\tilde{e}' = [(j-1)\tilde{e} + (e_m + e_f)/2]/j$.
*   **Stochastic Transition:** Expectation $E[V(j+1, \dots)]$ is taken over $z'$ using the Rouwenhorst transition matrix $\Pi$. For couples, $\Pi_{m,f}$ incorporates the intra-family correlation $\omega=0.1$.

### 4. Implementation Details & Integration

#### Backward Induction Orchestration
1.  Initialize $V_{16}(k, h, \tilde{e}) = 0$.
2.  Iterate $j$ from 15 down to 1.
3.  For each $j \ge 9$, solve `solve_retirement_phase`. Solve Singles first (needed for the married transition logic), then Couples.
4.  For each $j < 9$, solve `solve_working_phase`.
5.  Use **Linear Interpolation** for the continuous asset grid $k'$ and earnings grid $\tilde{e}$ when evaluating $V_{j+1}$.

#### Numba-Specific Constraints
*   **No Class Attributes:** Within `@njit` functions, constants from `config.yaml` and grids from `ParamsGenerator` must be passed as NumPy arrays or scalars.
*   **Grid Search vs. Optimizer:** For $k'$ and $m$, use a golden section search or a bounded Brent optimizer. For labor $n$ (if continuous), use the FOC where possible, otherwise grid search.
*   **Memory Management:** Pre-allocate value and policy function arrays (e.g., `V_single[age, k_idx, h_idx, e_idx]`) to avoid overhead.

#### Logic for "Married-to-Single" Transition
This is the most complex logic in the solver. When a spouse dies at age $j \ge 9$, the model transitions from $V^M$ to $V^S$. 
*   The survivor's value function $V^S$ must be solved **before** the married couple's $V^M$ at each age $j$.
*   The inheritance logic assumes 100% asset transfer to the survivor, which matches the paper's statement: "Married individuals who die... leave savings to their remaining spouse."

#### Bequests
While bequests are collected in the simulation, the solver treats the "Bequest received" as a lump-sum transfer (part of $y^d$) distributed to all workers. This value is determined in the GE loop and passed to the solver as a constant.
