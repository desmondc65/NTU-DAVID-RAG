In `household.py`, we implement the core decision-making engine of the OLG model. This module performs backward induction to solve for the value functions and policy rules (consumption, labor supply, and savings) across the entire state space.

### 1. State Space and Variable Definitions
The state $s$ is defined as $(i, a, b_1, b_2, e_1, e_2, m)$:
- **Age ($i$):** $21$ to $100$ (defined in `config.yaml` as `age_start` and `age_max`).
- **Assets ($a$):** End-of-period wealth, discretized into 27 nodes.
- **Average Historical Earnings ($b_1, b_2$):** For husband and wife, 15 nodes each.
- **Earning Ability ($e_1, e_2$):** Idiosyncratic shocks, 5 nodes each (Markov chain).
- **Marital Status ($m$):** 0 (Married), 1 (Single Male), 2 (Single Female).

### 2. Logic for `HouseholdProblem` Class

#### 2.1 Terminal Age Solution (`solve_terminal_age`)
At $i = 100$:
- The household has no future value ($V_{101} = 0$).
- All remaining assets, including interest and transfers, are consumed ($c = \text{Resources}$).
- Labor supply is determined by the static utility maximization (though for age 100, $h$ is typically 0 due to the retirement age $I_R=66$).
- The value function $V_{100}$ is calculated directly.

#### 2.2 Recursive Step (`solve_age_step`)
For each age $i$ from $99$ down to $21$:
1. **Expectation Over Shocks:** Calculate $E[V(i+1, s') | s]$. This involves:
   - Transition probabilities for $e_1, e_2$ (Rouwenhorst).
   - Mortality-adjusted probabilities for marital status $m'$ (survivorship $\phi_{1,i}, \phi_{2,i}$).
2. **Joint Labor Supply and Saving:** For a given state, the household solves:
   $$\max_{c, h_1, h_2} u(c, h_1, h_2; m, n_{m,i}) + \chi(h_1, h_2; m, n_{m,i}) + \beta E[V(i+1, s')]$$
   - **Married ($m=0$):** Unitary utility. Consumption is adjusted by $\lambda$ (degree of separate consumption): $c_{adj} = c / (1 + \lambda_{sep})$.
   - **Single ($m \in \{1, 2\}$):** Only one labor variable is active; the other is fixed at 0.
3. **Budget Constraint Implementation:**
   - Account for Gouveia-Strauss income tax ($\tau_I$).
   - Account for OASI payroll tax ($\tau_P$).
   - Account for Social Security benefits ($tr_{SS}$), including spousal/survivors logic.
   - Account for accidental bequests ($q_t$).

#### 2.3 Solving the Kuhn-Tucker System via Fischer-Burmeister
To handle constraints ($c > 0, 0 \le h_1 \le H_{max,1}, 0 \le h_2 \le H_{max,2}$), we transform the First-Order Conditions (Euler equation and MRS) into a nonlinear system using the Fischer-Burmeister function:
$$\phi(u, v) = u + v - \sqrt{u^2 + v^2} = 0$$
The system to solve via `scipy.optimize.root` includes:
- **Residual 1:** Intertemporal Euler equation.
- **Residual 2:** Husband's MRS (consumption vs leisure).
- **Residual 3:** Wife's MRS (consumption vs leisure).

#### 2.4 Random Utility from Home Production ($\chi$)
The paper uses a Gamma distribution for $\chi$ when $h_j = 0$ to ensure numerical smoothness:
- Calculate value $V_{work}$ (where $h$ is optimized) and $V_{home}$ (where $h=0$ is forced).
- Compute the expected value by integrating over the Gamma distribution density for $\chi$.
- This step follows the algorithm in Appendix A.2 to determine the probability of participation.

### 3. Numerical Efficiency (Numba and JIT)
- **Grid Interpolation:** The value function $V_{i+1}$ is interpolated on a 5D grid $(a, b_1, b_2, e_1, e_2)$ for each marital status. We use a Numba-jitted multi-linear interpolation to minimize overhead.
- **Parallelization:** Since the decision at age $i$ for a specific state is independent of other states at that age, we parallelize the loop over the state space nodes using `numba.prange`.
- **Pre-computation:** Survival probabilities and transition matrices are pre-computed and stored in the `Config` or `Utils` objects.

### 4. Logic Analysis for Government Policy in Household Logic
- **Historical Earnings Update:**
  - If $i < I_R$: $b'_{j} = \frac{(i-21)b_j + \min(w e_j h_j, \vartheta_{max})}{i-20}$.
  - If $i \ge I_R$: $b'_{j} = b_j$.
- **Social Security Benefit Formula:**
  - Implement the three-bracket PIA (90%, 32%, 15%) using `pia_bend_points` and `pia_replacement_rates` from `config.yaml`.
  - **Spousal Benefit:** For $m=0$, household receives $\max(\text{PIA}_1 + \text{PIA}_2, 1.5 \text{PIA}_1, 1.5 \text{PIA}_2)$.
  - **Survivors Benefit:** For $m \in \{1, 2\}$, household receives $\max(\text{PIA}_{own}, \text{PIA}_{deceased\_spouse})$.

### 5. Shared Interface References
- **Inputs:** `prices` (dict with $r, w, \psi, tr_{LS}, \phi$), `policy_params` (defines if spousal/survivors benefits are enabled/phased).
- **Outputs:** `NDArray` of value functions $V$ and policy functions $P$ (stored for forward induction in `economy.py`).

### 6. Critical Parameter Alignment (config.yaml)
- **Risk Aversion ($\gamma = 2.0$):** Affects the curvature of $V$.
- **Frisch Elasticity ($\alpha = 0.6530$):** Key for the MRS residuals.
- **Time Discount ($\beta = 0.9827$):** Adjusted for growth $\mu$ via $\beta_{adj} = \beta(1+\mu)^{\alpha(1-\gamma)}$.
- **Childcare Time Cost ($\kappa = 1.1655$):** Reduces female leisure endowment $1 - \kappa n_{m,i} - h_2$.
