The logic for `transition.py` involves simulating the dynamic path of the economy as it moves from the baseline steady state (with spousal and survivors benefits) to a new long-run equilibrium (without them). This requires solving for a sequence of factor prices and government policy parameters that satisfy market-clearing and budget-balancing conditions at every point in time.

### 1. Transition Horizon and Initialization
*   **Time Horizon ($T$):** The simulation should run for approximately 80–100 years to ensure the economy reaches the new steady state.
*   **Initial State:** The distribution of households at $t=0$ is the stationary distribution from the baseline steady state (`initial_ss`).
*   **Final State:** At $t=T$, the economy is assumed to have reached the new steady state (`final_ss`).
*   **Path Guesses:** Initialize the paths for factor prices $\{r_t, w_t\}_{t=1}^T$ and government variables $\{\psi_t, tr_{LS,t}, \phi_t\}_{t=1}^T$ by interpolating between the initial and final steady-state values.

### 2. Phased-in Policy Logic
The Social Security benefit function $tr_{SS,t}(i, b_1, b_2, m)$ varies over the transition path based on the cohort's age at the time of reform ($t=1$):
*   **Older Cohorts (Age 61+ at $t=1$):** 
    *   Condition: $i - (t-1) \ge 61$.
    *   Benefit: Use the old schedule (including spousal/survivors benefits), adjusted by $\psi_t$ and the ratio $\psi_0/\psi_T$ as described in Section 4.
*   **Younger Cohorts (Age 21- at $t=1$):**
    *   Condition: $i - (t-1) \le 21$.
    *   Benefit: Use the new schedule (own OA benefits only), adjusted by $\psi_t$.
*   **Transition Cohorts (Age 22-60 at $t=1$):**
    *   Condition: $22 \le i - (t-1) \le 60$.
    *   Benefit: A linear weighted average between the old and new schedules. The weight for the old schedule is $W = \frac{(i-20) - t}{40}$.

### 3. Iterative Solution Algorithm (Shooting Method)
To solve for the equilibrium transition path, implement the following loop:

1.  **Backward Induction (Household Problem):**
    *   Start from $t=T$ and move backward to $t=1$.
    *   At $t=T$, the value function $V_T$ is the final steady state's value function.
    *   For each $t < T$, solve the household's optimal decisions using the specific factor prices and policy parameters guessed for that year.
    *   Store the resulting value functions $V_t(s)$ and policy functions (savings, labor).

2.  **Forward Induction (Distribution Path):**
    *   Start from $t=1$ with the distribution $x_0(s)$.
    *   For each $t=1, \dots, T$, apply the policy functions derived in step 1 to the current distribution $x_{t-1}(s)$ to find $x_t(s)$ (the distribution at the start of next period).
    *   Handle mortality shocks and the aging process according to survival rates $\phi_{1,i}, \phi_{2,i}$ from `config.yaml`.

3.  **Aggregation and Market Clearing:**
    *   For each $t$, calculate aggregate Capital ($K_t$), Labor in efficiency units ($L_t$), and total tax revenues.
    *   **Government Budget Check:** 
        *   Update $\psi_t$ to balance the OASI budget ($T_{RSS,t} = T_{P,t} - T_{RO}$).
        *   Depending on the financing assumption (`Run 1(a)` or `Run 1(b)`):
            *   Update $tr_{LS,t}$ to balance the general budget.
            *   OR update $\phi_t$ (marginal tax rate) to balance the general budget.
    *   **Factor Price Check:** Calculate $r^{new}_t$ and $w^{new}_t$ using the marginal productivity conditions from the `Firm` module.

4.  **Convergence Check:**
    *   Compare the guessed paths for $\{r, w, \psi, \dots\}$ with the recalculated values.
    *   If the max difference exceeds a tolerance (e.g., $10^{-4}$), update the guesses using a damping factor (e.g., $Guess_{new} = \omega Guess_{recalc} + (1-\omega) Guess_{old}$) and repeat.

### 4. Welfare Calculation
Once the path converges, calculate the Consumption Equivalence Variation ($\lambda$):
*   **Current Cohorts ($t=1$):** Compare the value $V_1(i, a, b_1, b_2, e_1, e_2, m)$ after the policy change to the baseline steady state value $V_0$.
*   **Future Cohorts ($t > 1$):** Compare $V_t(21, 0, 0, 0, e_1, e_2, m)$ for newborns entering at year $t$ to the baseline newborn value.
*   The formula uses the CRRA utility parameters: $\lambda = [(\frac{V_{new}}{V_{old}})^{\frac{1}{\alpha(1-\gamma)}} - 1] \times 100$.

### 5. Alignment with Configuration (`config.yaml`)
*   **Demographics:** Use `pop_growth_nu` and `prod_growth_mu` to normalize aggregate variables.
*   **Aging:** The lifecycle ends at `age_max` (100).
*   **Growth Adjustment:** Ensure all wealth and earning variables are growth-adjusted as defined in the paper's model section.

### 6. Data Structures and Interfaces
*   The `TransitionPath` class will encapsulate the path solver.
*   **`solve_transition(guess_paths)`:** Orchestrates the backward/forward loops.
*   **`calculate_welfare_metric(path_V)`:** Post-processes the value functions into the $\lambda$ percentages for Table 4 and Figure 7.
*   Interaction with `HouseholdProblem` is critical; the solver must pass the correct `policy_params` (the phased-in benefit rules) for each specific year $t$ in the transition.
